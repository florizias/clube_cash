# 1) Decisão de arquitetura (a que mais funciona no mundo real)
Recomendo: Feature-first + Clean-ish (3 camadas)
Cada feature tem:
presentation (telas, widgets, controllers)
domain (entidades, casos de uso, regras)
data (repos, datasources Firebase, DTOs)

Isso evita:
“pasta screens gigante”
“services virando Deus”
“qualquer tela mexendo no Firestore”

8) Por que “ledger + idempotência” muda o jogo
Sem ledger, uma falha simples pode:
creditar pontos duas vezes
permitir resgate duplicado
bagunçar saldo sem rastro
Com ledger:
tudo é auditável
reversão é fácil
idempotência trava duplicações

9) Cloud Functions (mínimo indispensável no MVP)
Funções recomendadas
purchaseCreate
valida campos
cria compra como pending
grava expiresAt do comprovante (se você adotar retenção)
purchaseApprove(purchaseId)
calcula pontos (com % snapshot)
cria ledger earn com idempotencyKey
atualiza purchase.status=approved
purchaseReject(purchaseId, reason)
reason obrigatório
status rejected
rewardRedeem(rewardId)
verifica saldo
cria ledger burn
gera voucher único (e impede duplicar)
cleanupProofs (agendada)
apaga comprovantes vencidos do Storage

11) Router profissional (go_router)
Rotas com guard:
se não logado → auth
se logado e role=admin → libera admin
se role=partner → libera portal parceiro
user comum → app
Isso evita:
tela admin abrindo no celular de qualquer um
parceiro vendo compra de outro parceiro

12) Apps Web (Admin e Parceiro): como entregar bem
Você tem 2 abordagens:
A) Um único app com rotas e roles (mais rápido)
mesma base
menus mudam por role
build web única
B) 2 builds diferentes (mais profissional)
main_admin.dart
main_partner.dart
main_app.dart
cada um com router próprio e tema próprio
sso fica excelente para deploy separado.

13) Checklist de profissionalismo (que te poupa meses)
analysis_options.yaml com lints fortes
freezed e json_serializable para tudo
Result/Failure padronizado (sem try/catch espalhado)
logs estruturados (principalmente nas Functions)
paginação e índices no Firestore desde cedo
uploads sempre comprimidos + limite de tamanho
